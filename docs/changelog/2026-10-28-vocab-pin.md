# Ghim bộ từ vựng trong repo Rồng Giữ Ải (28/10/2026)

## Thay đổi và lý do

Cổng production G7 của map 1 yêu cầu bản game tự mang dữ liệu để chơi.
`public/vocabulary/` nay chứa bản chép nguyên byte từ commit repo cha
`18338405eebd9cfdbd6d6bf666ea79361c00a564`: `index.json`, đủ level 1–100
và `ATTRIBUTION.md`. Không lấy dữ liệu từ cây làm việc của repo cha.
`vocab.config.json` ghi commit và danh sách 102 file theo thứ tự chép;
`vocab-manifest.json` ghi phiên bản index và SHA-256 của từng file.

Vite phục vụ dữ liệu qua thư mục `public/` và đưa vào `dist/` khi build.
Bỏ plugin dev đọc thư mục cha cùng các import và biến không còn dùng.
Hàng `pnpm dev` trong `AGENTS.md` ghi đúng nguồn bản ghim. Chú thích bộ bài
bot ghi đúng nguồn là chuỗi `SOURCE` cố định trong chính `scripts/balance/deck.ts`;
mã bot không đổi.

`tests/vocab-pin.test.ts` có bảy ca kiểm: danh sách đầy đủ; pin và phiên bản;
SHA-256 và định dạng manifest; file theo index; bộ từ sau lọc người lớn/trẻ em
và chọn từ chiến đấu; luồng tải bộ bài ở mọi mức được kit hỗ trợ; quét đường
dẫn nguồn cha ngoài kit. Test chỉ đọc dữ liệu trong repo game, giả lập HTTP
bằng file cục bộ. Giới hạn level được đọc từ các guard trong mã kit, vì kit
chưa xuất hằng giới hạn.

## Cách cập nhật bản ghim

1. Chọn commit đầy đủ của repo cha, sửa `pin` trong `vocab.config.json`.
   Giữ thứ tự `index.json`, `levels/001.json` … `levels/100.json`,
   `ATTRIBUTION.md`; nếu phạm vi chương trình học đổi, đối chiếu lại mã kit.
2. Với từng đường dẫn trong config, chạy
   `git -C <repo-cha> show <pin>:shared/vocabulary/<file>` và ghi nguyên byte
   vào `public/vocabulary/<file>`. Không chép từ thư mục đang làm việc.
3. Tạo lại manifest theo thứ tự khóa ngoài `pin`, `version`, `files`:
   lấy `version` từ index vừa chép, băm SHA-256 từng file, xếp khóa file theo
   mã ký tự (`ATTRIBUTION.md` đầu tiên). JSON thụt hai dấu cách, xuống dòng cuối.
4. Chạy `pnpm check`, kiểm SHA-256 trong `dist/vocabulary/`, kiểm bản chép
   đứng riêng và xác nhận golden không đổi. Khi Mac dùng chung bị nhiễu test
   hiệu năng HUD, chạy `VITEST_MAX_FORKS=1 VITEST_MIN_FORKS=1 pnpm check`.
   Không cập nhật golden để chấp nhận thay đổi dữ liệu.

## Số đo và giới hạn

- 102 file nguồn, 2.666.590 byte; manifest 9.365 byte. Tổng bản ghim có manifest:
  103 file, 2.675.955 byte; index phiên bản 1, 100 level, 18.000 mục từ.
- Mọi level còn ít nhất 150 mục sau bộ lọc người lớn hoặc trẻ em; sau chọn
  ứng viên chiến đấu, mức nhỏ nhất là 139 từ (level 95).
- Trước: 51 file / 453 test. Sau: 52 file / 460 test, tăng đúng bảy ca mới.
  `pnpm check` một worker đạt kiểm hash kit, test, TypeScript và Vite build.
  Lần chạy mặc định đầu tiên có một lỗi đo hiệu năng HUD: 1,193 ms so với
  ngưỡng dưới 1 ms; không sửa test hoặc mã HUD.
- Mã hiện tại cho lưu level vượt 100: mức 100 tạo cặp ứng viên `[100, 101]`,
  nhưng `defaultEntries()` lọc qua index nên chỉ tải file 100. Lưu 101 tạo
  cặp `[101, 102]`, chỉ tải index và nhận bộ bài rỗng. Đã chuyển lỗi giới hạn
  mức lưu này cho Claude trong báo cáo phiếu 094; phiếu không cho sửa `src/`.
  Test xác nhận đủ file cho mọi request thực tế trong miền 1–100; không khẳng
  định bộ bài luôn có từ khi bản lưu nằm ngoài miền đó.
